# Microcontroller Lab

A collection of microcontroller laboratory programs and practical
exercises for the **B.E. Computer Science and Engineering** curriculum
under the **VTU 2022 Scheme**.

This repository keeps laboratory source files organized for study,
practice, revision, and reference.

## Repository Contents

The repository contains lab programs and related source files.
Experiment labels such as **5A** and **5B** are kept separate where an
experiment has multiple parts.

Topics may include:

-   ARM assembly language programming
-   Register and data-transfer operations
-   Arithmetic and bitwise logical operations
-   Array and memory operations
-   C programs used in laboratory exercises

> **Important:** Refer to the source files and your current lab manual
> for the exact experiment titles, numbering, and expected outputs.

## Tools and Environment

Use the tools required by your course and target platform. Depending on
the source file, this may include:

-   An ARM assembler or simulator for `.asm` and `.s` files
-   A C compiler for `.c` files
-   An IDE or debugging environment provided by your institution

## Getting Started

Clone or download this repository:

``` bash
git clone https://github.com/Suhas810/Microcontroller_Lab.git
cd Microcontroller_Lab
```

Open the source file for the experiment you want to study, then assemble
or compile it using the appropriate tool for its language and target.
Run it in the required simulator or environment and compare the results
with your lab manual.

## File Naming Convention

Keep experiment labels consistent with your lab manual. A descriptive
naming style can make files easier to identify:

``` text
<experiment-number>_<short-topic-name>.<extension>
```

Examples:

``` text
5A_data_transfer.asm
5B_arithmetic_logical_operations.asm
```

These are naming examples only. Retain existing filenames if they
already match the official experiment numbering.

## Adding or Updating Programs

When contributing a new program:

-   Use a clear, descriptive filename.
-   Add comments where they help explain the logic.
-   Preserve experiment numbering from the lab manual.
-   Verify the program in the appropriate environment before marking it
    as tested.
-   Include any relevant input, output, or setup notes when useful.
